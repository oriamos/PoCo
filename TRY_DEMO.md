# Try PoCo with the synthetic demo slide

This walk-through uses `resources/dataset_files/test/test_img.tif`, a **synthetic** two-channel slide generated by
[`make_test_img.py`](resources/dataset_files/test/make_test_img.py). No laboratory image is involved. Its ground truth
(the spot positions it was built with) is stored next to it in `test_img.truth.json`.

Use the demo to learn the workflow. It does not show how accurate the detectors are on real slides; see
[docs/STATUS_AND_RESULTS.md](docs/STATUS_AND_RESULTS.md) for that.

## 1. Start the demo

You need Python 3.10–3.13 and `make`. From a clone of the repository:

```bash
make app-install   # first run only: creates .venv and installs the Python dependencies
make demo          # copies the demo slide and starts the app on http://127.0.0.1:8000
```

`make demo` prints the path of the copied slide. It keeps everything in a separate folder:

| Path | What it is |
|---|---|
| `demo-data/input/test_img.tif` | the copied demo slide (you open this file in the app) |
| `demo-data/app/` | the application's own data (analyses, detection results) |

Your normal data folder is not used by `make demo`.

## 2. Open the slide

1. In the left panel, click **Open from disk…** and enter the full path of `demo-data/input/test_img.tif` (the path is printed by
   `make demo`).
   The file is opened in place, so Save writes its outputs next to it (see step 7).
   You can also drag the file into **Drop TIFF(s) here**; the outputs are then written to the folder you choose at save time.
2. The app shows an analysis called `test_img` with the status *needs channel mapping*.

## 3. Map the channels

Open the mapping dialog and confirm:

* channel 0 (page 0) = **red**
* channel 1 (page 1) = **green**

File names and page order only suggest a role; the app never confirms a channel for you. Until you confirm the mapping, the
processed views and detection are not available. See [USER_GUIDE section 2](docs/app/USER_GUIDE.md#2-channel-mapping-mandatory).

## 4. Choose the counting fields

Create the counting grid and choose which fields to count, following
[USER_GUIDE section 3](docs/app/USER_GUIDE.md#3-regions-and-exclusions). Try **Randomise** once, then set the grid back if you want
the fixed layout. The seed shown with the grid reproduces that layout. The lab template numbers fields 1 to 24, so choose a grid of at
most 24 fields (the demo slide's own grid is 4 columns; use 6 rows).

## 5. Detect

Keep the default parameters for a first run. Start detection from the **Detect** tab. Big-FISH runs on both channels and proposes
spots; a spot seen in both channels is shown as yellow. Detection runs in the background; the status changes to *in review* when it finishes.
See [USER_GUIDE section 5](docs/app/USER_GUIDE.md#5-detection).

## 6. Review

Go through the review queue and approve or reject objects, as described in
[USER_GUIDE sections 6 to 9](docs/app/USER_GUIDE.md#6-review-queue). Nothing is counted as final until you approve it.
Agreement between the two detectors is not ground truth; check the objects by eye.

## 7. Save and export

Click **Save** (or follow [USER_GUIDE section 11](docs/app/USER_GUIDE.md#11-save-labelled-scan-and-csv-next-to-the-original)).
For the opened file, the outputs are written in `demo-data/input/`:

| File | Content |
|---|---|
| `test_img_labeled.tif` | the scan with the approved objects drawn on it |
| `test_img.csv` | per-field counts for the slide |
| `experiment_counts.csv` | the running table of saved slides in that folder |

These names are produced by [`src/polony_app/export/slide_save.py`](src/polony_app/export/slide_save.py) and checked by the
automated demo test (see the last section).

## What to expect

* The app opens with the synthetic slide and nothing else.
* Counts depend on the parameters and on which fields you choose; the demo does not have a fixed "correct" number to match.
* The demo file was generated with known spot positions, recorded in `test_img.truth.json`. It is a teaching example, not a benchmark.

## Reset the demo

```bash
make demo-reset    # deletes ./demo-data (the copied slide and the demo analyses)
make demo          # start again
```

`make demo-reset` removes only `./demo-data`. Your own data folders and the repository files are not touched.

## Automated check of this path

`tests/app/test_demo_smoke.py` checks that the demo file is the documented synthetic example, imports it through the API, maps
the channels, runs real Big-FISH detection, reads counts and downloads the export bundle. A second test opens the file in place,
generates a 4 x 6 grid, detects, saves, and asserts that `test_img_labeled.tif`, `test_img.csv` and `experiment_counts.csv` appear next to
the scan. They run with the backend tests (`make app-test`) and in CI.
