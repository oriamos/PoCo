# Try PoCo with the synthetic demo slide

Uses `resources/dataset_files/test/test_img.tif`, a **synthetic** two-channel slide generated by [`make_test_img.py`](resources/dataset_files/test/make_test_img.py); no laboratory image. Its ground truth (the spot positions it was built with) is in `test_img.truth.json`. It teaches the workflow; it is a teaching example, not a benchmark, and does not show detector accuracy on real slides ([docs/STATUS_AND_RESULTS.md](docs/STATUS_AND_RESULTS.md)). There is no fixed "correct" count: counts depend on parameters and chosen fields.

## 1. Start the demo

Needs Python 3.10–3.13 and `make`. From a clone of the repository:

```bash
make app-install   # first run only: creates .venv and installs the Python dependencies
make demo          # copies the demo slide and starts the app on http://127.0.0.1:8000
```

`make demo` prints the slide's path and keeps everything in a separate folder (your normal data folder is not used):

| Path | What it is |
|---|---|
| `demo-data/input/test_img.tif` | the copied demo slide (open this in the app) |
| `demo-data/app/` | the application's own data (analyses, detection results) |

## 2. Open the slide

Left panel: **Open from disk…**, enter the full path of `demo-data/input/test_img.tif`. It is opened in place, so Save writes next to it (step 7). Or drag it into **Drop TIFF(s) here**; outputs then go to the folder you choose at save time. The app shows analysis `test_img` with status *needs channel mapping*.

## 3. Map the channels

Confirm channel 0 (page 0) = **red**, channel 1 (page 1) = **green**. File names and page order only suggest a role; the app never confirms a channel for you, and without confirmation processed views and detection are unavailable. See [USER_GUIDE section 2](docs/app/USER_GUIDE.md#2-channel-mapping-mandatory).

## 4. Choose the counting fields

Create the grid and choose fields ([USER_GUIDE section 3](docs/app/USER_GUIDE.md#3-regions-and-exclusions)). Try **Randomise** once, then set the grid back; the seed shown with the grid reproduces the layout. The lab template numbers fields 1 to 24, so use at most 24 fields (demo grid: 4 columns, 6 rows).

## 5. Detect

Keep the default parameters and start detection from the **Detect** tab. Big-FISH runs on both channels; a spot in both is yellow. Detection runs in the background; the status becomes *in review* when done. See [USER_GUIDE section 5](docs/app/USER_GUIDE.md#5-detection).

## 6. Review

Approve or reject objects in the review queue ([USER_GUIDE sections 6 to 9](docs/app/USER_GUIDE.md#6-review-queue)). Nothing is final until you approve it. Agreement between the two detectors is not ground truth; check objects by eye.

## 7. Save and export

Click **Save** ([USER_GUIDE section 11](docs/app/USER_GUIDE.md#11-save-labelled-scan-and-csv-next-to-the-original)). For the opened file, outputs go to `demo-data/input/` (names from [`src/polony_app/export/slide_save.py`](src/polony_app/export/slide_save.py)):

| File | Content |
|---|---|
| `test_img_labeled.tif` | the scan with the approved objects drawn on it |
| `test_img.csv` | per-field counts for the slide |
| `experiment_counts.csv` | the running table of saved slides in that folder |

## Reset the demo

```bash
make demo-reset    # deletes ./demo-data only (copied slide and demo analyses); your data and the repository are untouched
make demo          # start again
```

## Automated check of this path

`tests/app/test_demo_smoke.py` checks the demo file is the documented synthetic example, imports it through the API, maps the channels, runs real Big-FISH detection, reads counts and downloads the export bundle. A second test opens the file in place, generates a 4 x 6 grid, detects, saves, and asserts that `test_img_labeled.tif`, `test_img.csv` and `experiment_counts.csv` appear next to the scan. Both run with `make app-test` and in CI.
